## Done since (e5d572e, pushed) — was "in progress"

Found by running the site and bot against the **real June data** loaded into a
throwaway local Postgres DB `lc_rehearsal` (never Neon):

1. **Admin user timeline 500 on Postgres** — `services.get_user_activity_timeline`
   used `COALESCE(json_column, '')`. Fixed with `CAST(... AS TEXT)`. Verified: all
   103 GET routes × 3 roles return no 5xx on real data.
2. **`!confirm` crashes on Postgres (launch blocker)** — `offers.confirm_offer`
   stores `create_loan`'s return (the 13-digit public loan ID, text) in
   `loan_offers.loan_db_id INTEGER` → overflow after the loan is saved; borrower
   gets no reply. Fix: new `scripts/migrations/020_loan_offer_loan_id_text.sql`
   (column → TEXT), `schema.sql` updated, `create_loan` docstring corrected.
   **User must run `python scripts/run_migrations.py` (Neon) after pushing.**
3. **Bot cooldown silently dropped real commands** — 15 s per user per command,
   so a second `!paid_with_id` for a *different* loan was ignored. Fixed in
   `main.py` `_is_rate_limited`: cooldown now only blocks the *identical* command
   text (a double post).
